# Analysis guides

## Per-chunk ledger (keep as files so work can resume)

For every chunk record:
- date range and first/last message id
- speakers present
- events (what happened, ids)
- communication patterns
- positive and negative evidence (with ids)
- contradictions
- limits (missing media, sparse month, partial export)
- quotes with ids

Also keep a coverage log: which chunks were actually read, which were not. Only claim message counts "reviewed" when they can be computed.

## Turning point template

For each turning point:
1. Date or range, with the message ids the identification rests on.
2. State of the relationship before the event.
3. What happened in the chat, separate from the presumed cause.
4. Each speaker's reaction.
5. State after: what changed and what stayed.
6. Whether the change lasted, reversed, or there is not enough later documentation.
7. Alternative reading and confidence.

Windows: up to 30 days before and after by default; up to 90 days or adjacent periods if the chat is sparse, with the reason stated. Show window dates and message volume in each. Do not compare raw counts across unequal windows (compare rates only with a defined denominator, and prefer describing content).

## Counter-evidence habit

For each tentative trait or pattern, before writing it down, search the ledger for at least one example that points the other way and for an explanation that does not involve the person's character (workload, time zone, a bad week, a language switch, a topic that only concerns this person).

## Pair analysis in groups

Analyze a pair only when the addressee is identifiable (reply quote, name mention, direct context). Do not attribute a message sent to the group to every pair.
